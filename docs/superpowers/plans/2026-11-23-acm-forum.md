# ACM Forum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a member forum to acmgazi.org: Gazi-only accounts, article editor with images, admin approval, comments, and a "Son Yazılar" block on the home page.

**Architecture:** Hugo keeps serving static page shells in the existing theme. Browser-side ES modules in `static/js/forum/` talk to Supabase (Auth, Postgres with row-level security, Storage). All security lives in the database (`supabase/schema.sql`); pages only hide UI.

**Tech Stack:** Hugo extended 0.135.0, Supabase (project `eyjnvkkcafmykcgihseq`), `@supabase/supabase-js@2.45.4`, `easymde@2.18.0`, `marked@14.1.2`, `dompurify@3.1.7` (all from cdn.jsdelivr.net, exact versions), Node 24 built-in test runner (`node --test`), Playwright MCP for browser checks.

**Spec:** `docs/superpowers/specs/2026-11-22-acm-forum-design.md`

## Global Constraints

- Branch: all work on `feature/acm-forum`. **Never push to `main` before Task 11** — a push to `main` deploys the live site.
- Do not change existing theme tokens, nav styling, header, footer or existing pages, except: the nav gets the "ACM Forum" link (desktop + mobile lists) and the home page "Haberler" block becomes "Son Yazılar" + "Haberler".
- UI text in Turkish. Colours only from `themes/ananke/assets/ananke/css/_styles.css` variables (`--foreground-primary`, `--foreground-primary-dim`, `--foreground-link`, `--background-primary`, `--background-primary-dim`, `--accent`) and the `.glass-card` look. Font: Outfit (already loaded).
- Every page must work at **1440×900 (desktop)** and **390×844 (phone)** with no horizontal scroll; layout switches at the site's existing breakpoint `max-width: 1000px`.
- E-mails are never shown publicly. Byline format: `Ad Soyad · Bölüm · Sınıf` (e.g. `Ayşe Yılmaz · Bilgisayar Mühendisliği · 2. sınıf`).
- Sign-up allowed only for `gazi.edu.tr` or any subdomain of it, plus addresses in `signup_allowlist` (seeded with `istisna@example.com`).
- Only the publishable key (`sb_publishable_LLAKiUOiRDzsgBNADZh5SQ_hZ2oYML9`) goes in the repo. Never the service-role/secret key.
- All user content rendered as HTML goes through `marked` → `DOMPurify.sanitize`. Comments render as plain text (`textContent`).
- Private forum pages (`giris`, `yeni`, `profilim`, `admin`) set `private: true` in front matter (the theme then emits `noindex`).
- **Per-page workflow (user requirement):** each page task starts with a design checkpoint (text mockup for desktop + phone, user approves) and ends with a review checkpoint (screenshots at both sizes + every listed check passing, user approves) before the next task starts.

## Review Focus

1. **Long/unbroken text on a phone** (Turkish characters, 200-char URLs, code blocks in titles/bodies/comments) — must wrap or scroll inside its box; page never scrolls sideways. Tests: Tasks 6 and 7 browser checks.
2. **Logged-out or expired session opening a protected page** (`/forum/yeni/`, `/forum/profilim/`, `/forum/admin/`) — redirect to `/forum/giris/?next=<page>` and return there after login. Tests: Task 3 (`requireUser`) + browser checks in Tasks 5, 6 and 9.
3. **Hostile Markdown** (`<script>`, `<img onerror>`, `javascript:` links, raw `<iframe>`) in articles and comments — nothing executes. Tests: Task 2 `renderMarkdown` unit tests + Task 7 browser check.
4. **Bad or hidden article id** in `/forum/yazi/?id=` (missing, not a UUID, unknown, pending/rejected viewed by a stranger) — shows "Yazı bulunamadı", no crash, no leak. Tests: Task 2 `getIdParam` + Task 4 RLS + Task 7 browser check.
5. **Supabase paused or unreachable** — forum pages show a Turkish error with a retry button; on the home page "Son Yazılar" hides and the rest of the site works. Tests: Tasks 7 and 10 browser checks with the network request blocked.

### Task 4: Database schema, rules and RLS tests

**Files:** Create `supabase/schema.sql`, `supabase/test-setup.sql`, `tests/forum/rls.test.js`, `docs/forum-supabase-setup.md`.

**Interfaces (Produces — exact database names):**
- Types: `year_level` enum (`hazirlik,1,2,3,4,yuksek_lisans,doktora,mezun`), `user_role` enum (`member,admin`), `post_status` enum (`pending,approved,rejected`).
- `profiles(id uuid pk → auth.users on delete cascade, full_name text not null, major text not null default '', year year_level null, role user_role not null default 'member', created_at timestamptz default now())`
- `posts(id uuid pk default gen_random_uuid(), author_id uuid not null → profiles on delete cascade, title text check 5–150 chars, body_md text check 50–50000 chars, status post_status not null default 'pending', reject_reason text null, created_at, updated_at, approved_at, approved_by uuid → profiles)` + index `(status, approved_at desc)`.
- `comments(id uuid pk, post_id uuid → posts on delete cascade, author_id uuid → profiles on delete cascade, body text check 1–2000 chars, created_at)` + index `(post_id, created_at)`.
- `signup_allowlist(email text pk)` seeded `istisna@example.com`; no grants to `anon`/`authenticated`.
- `is_admin(): boolean` (security definer, stable).
- Trigger `handle_new_user` (after insert on `auth.users`) → inserts profile from `raw_user_meta_data` (`full_name` default = e-mail local part, `major` default `''`, `year` null if absent/invalid).
- Trigger `posts_author_guard` (before update on `posts`): if not admin → force `status='pending'`, clear `reject_reason`, `approved_at`, `approved_by`, keep `author_id`; always set `updated_at = now()`.
- Trigger `profiles_role_guard` (before update on `profiles`): non-admins cannot change `role`.
- RPCs (security definer, `search_path = ''`, `is_admin()` checked first, raise `'forbidden'` otherwise): `approve_post(p_id uuid)`, `reject_post(p_id uuid, p_reason text)` (reason required, 3–500 chars), `admin_list_members()` → `(id, full_name, major, year, role, email, created_at)`, `set_member_role(p_user uuid, p_role user_role)` (refuses to demote the last admin).
- RLS policies exactly as the spec's "Rules" section; `profiles` public select limited via a view-free approach: grant `select (id, full_name, major, year, role)` on `profiles` to `anon, authenticated` (column grants), RLS select `true`.
- Sign-up hook `public.hook_before_user_created(event jsonb) returns jsonb`: allows when the e-mail's domain equals `gazi.edu.tr` or ends with `.gazi.edu.tr`, or the e-mail is in `signup_allowlist`; otherwise returns `{"error": {"http_code": 403, "message": "Sadece @gazi.edu.tr uzantılı adreslerle kayıt olunabilir."}}`. Execute granted only to `supabase_auth_admin`.
- Storage: bucket `forum-images` (public, `file_size_limit` 5242880, `allowed_mime_types` jpeg/png/webp/gif); policies: insert only into `<auth.uid()>/…`; delete by owner folder or admin; public read.

**Interfaces:**
